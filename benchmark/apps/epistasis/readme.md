# Epistasis Detection -- Bitstream Benchmark

## Overview

The epistasis benchmark implements a **2x2 contingency table** for genome-wide
association studies (GWAS) using bitstream programs. Given two single-nucleotide
polymorphisms (SNPs) and a set of valid individuals, the program computes the four
cells of the contingency table -- counting how many individuals carry each combination
of genotypes -- using bitwise AND/NOT operations followed by `popcount()` reductions.

In genetics, **epistasis** is the phenomenon where the effect of one gene depends on
the presence of another gene. GWAS datasets contain hundreds of thousands of SNPs
measured across hundreds of thousands of individuals. Testing all pairs means billions
of contingency tables, making this an ideal target for GPU parallelism.

This benchmark exercises a pure **stream-to-integer reduction pattern**: every
output is an `int` produced by `popcount()` with no stream output alongside.
Two other benchmarks (BitWeaving and BitFunnel) also call `popcount()`, but
each emits a stream result with a single integer count; Epistasis is the only
benchmark whose outputs are entirely integers (four counts, no stream).

---

## Dataset

The benchmark uses **synthetic data** exclusively. No external datasets are required.

- **Fixed test vectors**: 6 hand-crafted cases covering edge conditions (all 1/1,
  all 1/0, mixed half, missing data with alternating validity mask, no valid
  individuals, and a single individual).
- **Random test vectors**: 100 random 16-bit trials and 50 random 64-bit trials
  generated with `randint()`.
- **Large-scale**: 1M-bit-wide streams (snp_a, snp_b, valid) generated with
  `getrandbits(1_000_000)`, representing ~15,625 words of GPU SIMD parallelism.

The fixed and small random tests verify the bitstream contingency table against a
Python scalar reference that loops over individuals one at a time. The large-scale
and tier tests instead use a direct popcount reference (`bin(...).count('1')`),
which is equivalent but fast enough at GPU scale. The large-scale and tier tests
also verify that the four counts sum to `popcount(valid)` as a sanity check.

### Real-world scale context

Large single-cohort biobanks such as UK Biobank contain ~500,000 individuals. A
1M-bit stream comfortably covers single-cohort biobanks in this class, though the
Million Veteran Program enrollment exceeds 1M and published GWAS meta-analyses
(e.g., the 5.4M-individual height meta-analysis) aggregate millions of individuals
across consortia. On a GPU with 64-bit words, 1 million individuals occupy
approximately 15,625 words of SIMD parallelism per stream operation.

## Tutorial

### What is epistasis detection?

In genetics, **epistasis** is the phenomenon where the effect of one gene depends on
the presence of another gene. Genome-wide association studies (GWAS) test every pair of
single-nucleotide polymorphisms (SNPs) for epistasis by building a genotype contingency
table counting how many individuals carry each combination of genotypes. Real diploid SNP
genotypes have three classes each, so a faithful table is **3x3** with nine genotype
combinations. This benchmark uses a simplified binary allele-presence encoding (detailed
in "The bitwise formulation" below), which reduces the table to the **2x2** form.

Given two SNPs (A and B) and a set of valid individuals, the table looks like this:

|                  | SNP B = 1 | SNP B = 0 |
|------------------|-----------|-----------|
| **SNP A = 1**    | n_11      | n_10      |
| **SNP A = 0**    | n_01      | n_00      |

Each cell counts the number of individuals with that particular combination.
The benchmark stops after building this table; a downstream pipeline would then
feed the counts (combined with phenotype or case/control labels not modelled
here) into a statistical interaction test such as chi-squared or log-linear.

GWAS datasets contain hundreds of thousands of SNPs measured across hundreds of
thousands of individuals. Testing all pairs means billions of contingency tables.

### The scalar approach (and its limitations)

The standard scalar implementation loops over all individuals and increments the
appropriate counter based on each individual's genotypes:

```python
def contingency_table(snp_a, snp_b, valid, n_individuals):
    n_11 = n_10 = n_01 = n_00 = 0
    for i in range(n_individuals):
        if not valid[i]:
            continue
        a = snp_a[i]
        b = snp_b[i]
        if a and b:
            n_11 += 1
        elif a and not b:
            n_10 += 1
        elif not a and b:
            n_01 += 1
        else:
            n_00 += 1
    return n_11, n_10, n_01, n_00
```

This has several characteristics that limit performance:

- **Sequential**: each individual is processed one at a time.
- **Branchy**: each individual requires two to three branch decisions.
- **Poor SIMD utilization**: the branches prevent vectorization.

For a GWAS study with 500,000 SNPs there are about 125 billion SNP pairs, hence 125
billion contingency tables. With 500,000 individuals per table, that is roughly 6.25e16
iterations of this loop in total.

### The bitwise formulation

Real diploid SNP genotypes take three values (`0/0`, `0/1`, `1/1`), so a faithful
encoding uses two bits per individual. For this benchmark we use a simplified
**binary allele-presence encoding**: bit *i* is 1 iff individual *i* carries the
target allele at that SNP (or any other 1-bit-per-individual reduction of the
genotype). With this encoding the four cells of the contingency table reduce to
bitwise operations and population counts:

```
cell_11 = snp_a & snp_b & valid        -- both present
cell_10 = snp_a & ~snp_b & valid       -- A present, B absent
cell_01 = ~snp_a & snp_b & valid       -- A absent, B present
cell_00 = ~snp_a & ~snp_b & valid      -- both absent
```

Each cell stream has a 1 at bit position *i* if and only if individual *i* belongs to
that cell. The count is then `popcount()` of each cell stream.

### Why branches disappear

In the scalar version, each individual requires conditional logic to determine which
counter to increment. In the bitstream version, all individuals are classified
simultaneously by the AND/NOT operations. There are no branches -- every bit position
is processed by the same fixed sequence of operations.

### Why this is efficient on a GPU

Each bitwise operation processes 64 individuals per 64-bit word. For 1 million
individuals, each AND or NOT operates on approximately 15,625 words. The total work is
10 bitwise operations (2 NOT + 8 AND; each cell stream needs a two-stage AND
chain `x & y & valid`) plus 4 population counts -- regardless of the number of
individuals. Scaling from 64 individuals to 1 million requires no additional
operations, only wider streams.

## .bs Program Details

The complete program lives at `src/epistasis.bs`. Here is the full listing with
annotations:

### Declarations

```
// Epistasis: 2x2 contingency table for SNP pairs
// Source: Wan et al., "BOOST" (2010); Yung et al., "GBOOST" (2011)
input stream snp_a
input stream snp_b
input stream valid
output int n_11
output int n_10
output int n_01
output int n_00
```

The program takes three input streams -- the genotypes for SNP A, the genotypes for
SNP B, and a validity mask indicating which individuals to include. It produces four
integer outputs, one for each cell of the contingency table. BitWeaving and BitFunnel
also use `output int`, but each combines it with a stream output; this is the only
benchmark whose outputs are entirely integers.

### Precomputation

```
stream not_a = ~snp_a
stream not_b = ~snp_b
```

Compute the complement of each SNP stream once, since both `not_a` and `not_b` are
used twice each.

### Contingency table

```
n_11 = popcount(snp_a & snp_b & valid)
n_10 = popcount(snp_a & not_b & valid)
n_01 = popcount(not_a & snp_b & valid)
n_00 = popcount(not_a & not_b & valid)
```

Each line computes one cell. The inner expression (e.g., `snp_a & snp_b & valid`) is a
stream where bit *i* is 1 if and only if individual *i* belongs to that cell. The
`popcount()` reduces the stream to an integer count.

### Op count

- 2 NOT operations (`~snp_a`, `~snp_b`)
- 4 AND chains, each with 2 ANDs: `(x & y & valid)` = 2 ANDs, so 4 * 2 = 8 ANDs
- 4 `popcount` reductions

Total: **2 NOT + 8 AND = 10 bitwise ops** plus **4 popcount reductions**.

The program is straight-line (no loops, no branches). It is one of the simplest
programs in the benchmark suite, but it uniquely demonstrates the stream-to-integer
reduction capability.

### DSL features used

| Feature        | How it is used                                     |
|----------------|----------------------------------------------------|
| `&` (AND)      | Combine SNP genotypes with validity mask            |
| `~` (NOT)      | Invert genotype streams for the "absent" cells      |
| `popcount()`   | Count individuals in each contingency table cell    |
| `output int`   | Declare integer outputs for the four counts         |

Notably, epistasis uses **only AND and NOT** for its bitwise operations -- no OR, XOR,
SHIFT, loops, arrays, or parameters. Combined with `popcount`, this makes it the
benchmark with the smallest DSL feature footprint. BitWeaving and BitFunnel also
use the `popcount` reduction, but they reduce a single result stream to one count;
only epistasis collapses its inputs entirely into integer outputs.

## Running

### Prerequisites

Make sure you are in the project root directory and have Python 3 available. No
external packages are required.

### Standalone runner

```bash
python3 benchmark/apps/epistasis/src/run.py
```

This runs every test whose data is present — 9 from a clean checkout,
all 12 once the three tiers have been generated with
`generate_tests.py --tier <t>`:

```
Epistasis (2x2 Contingency Table) Bitstream Benchmark

  [PASS] All 1/1  (8 individuals, 14 ops)
  [PASS] All 1/0  (8 individuals, 14 ops)
  [PASS] Mixed half  (8 individuals, 14 ops)
  [PASS] Missing data  (8 individuals, 14 ops)
  [PASS] No valid  (8 individuals, 14 ops)
  [PASS] Single individual  (1 individuals, 14 ops)
  [PASS] Random 16-bit x100  (100 individuals, 1400 ops)
  [PASS] Random 64-bit x50  (50 individuals, 700 ops)
  [PASS] Large 1M individuals  (1000000 individuals, 14 ops)
  [PASS] Tier medium (1.33B individuals)  (1330000000 individuals, 14 ops)   # after --tier medium
  [PASS] Tier small (133M individuals)  (133000000 individuals, 14 ops)      # after --tier small
  [PASS] Tier large (13.3B individuals)  (13300000000 individuals, 14 ops)   # after --tier large

Results: 12 passed, 0 failed, 12 total
ALL TESTS PASSED
```

For the two multi-case lines, the leading number printed by the runner is the
`bitlength` field from `tests.json`, which for these bundles holds the
**case count** rather than per-case width. So `(100 individuals, 1400 ops)`
means 100 cases of 16-bit streams (100 cases x 14 ops = 1400 ops), and
`(50 individuals, 700 ops)` means 50 cases of 64-bit streams. All other
rows display the actual per-stream width.

### Test suite (12 tests)

The runner executes nine fixed/standalone cases plus three tier files
(small/medium/large). The six fixed cases cover edge conditions; "Random 16-bit
x100" and "Random 64-bit x50" are multi-case bundles of narrow random trials;
"Large 1M individuals" and the three tier entries are single wide-stream cases
used by the main benchmark driver.

| Test                   | Individuals    | Description                                              |
|------------------------|----------------|----------------------------------------------------------|
| All 1/1                | 8              | Every individual has both SNPs present                   |
| All 1/0                | 8              | Every individual has SNP A but not SNP B                 |
| Mixed half             | 8              | SNP A and SNP B each present in different halves         |
| Missing data           | 8              | Only alternating individuals are valid                   |
| No valid               | 8              | Validity mask is all zeros (all individuals excluded)    |
| Single individual      | 1              | Minimal case: one individual, SNP A=1 and SNP B=0        |
| Random 16-bit x100     | 100 x 16-bit   | 100 random 16-individual trials, run as a multi-case file |
| Random 64-bit x50      | 50 x 64-bit    | 50 random 64-individual trials, run as a multi-case file  |
| Large 1M individuals   | 1,000,000      | GPU-scale: 1M individuals processed simultaneously       |
| Tier small             | 133,000,000    | ~50 MB tier bundle (synthetic)                            |
| Tier medium            | 1,330,000,000  | ~500 MB tier bundle (synthetic)                           |
| Tier large             | 13,300,000,000 | ~5 GB tier bundle (synthetic)                             |

The fixed and small random tests verify the bitstream contingency table against a
Python scalar reference that loops over individuals one at a time; the large-scale
and tier tests use an equivalent direct-popcount reference. The tests cover edge
cases (all same genotype, no valid individuals, single individual), random inputs at
multiple widths, and a large-scale test demonstrating GPU-level parallelism.

The large-scale test generates three random 1,000,000-bit streams (snp_a, snp_b,
valid), runs the bitstream program, and checks that the four counts match a reference
computed using Python's `bin(...).count('1')`. It also verifies that the four counts
sum to `popcount(valid)` as a sanity check.
