# Edit Distance (Myers' Bit-Parallel Algorithm) — Bitstream Benchmark

## Overview

This benchmark implements Myers' bit-parallel algorithm for computing Levenshtein edit
distance using the bitstream DSL. Each bit position is a different text being compared
against the same pattern. The algorithm computes edit distances for all texts
simultaneously in O(N*M) bitwise operations, where N is the text length and M is the
pattern length.

The pattern must be nonempty (M >= 1): Myers' bit-vector form encodes the pattern as
an M-bit vector, so the degenerate empty-pattern case (where the distance is simply N)
is outside this benchmark's scope.

> Myers, G. "A Fast Bit-Vector Algorithm for Approximate String Matching Based on
> Dynamic Programming." *Journal of the ACM* 46(3):395-415, 1999.

**Why edit distance for bitstreams?** Myers' 1999 algorithm is the canonical example of
bit-parallel dynamic programming. It encodes the DP matrix columns as bit-vectors and
updates them using carry-propagating addition, XOR, and boolean logic. The algorithm is
widely used in bioinformatics (sequence alignment), text processing (spell-checking,
fuzzy search), and information retrieval.

**Bitstream adaptation.** In the standard Myers algorithm, each bit in a machine word
represents a different row of the DP matrix. In our bitstream version, each bit position
represents a *different text* being compared against the same pattern. This transposes
the parallelism: instead of processing M pattern positions per word, we process K texts
per stream. The algorithm structure (carry-propagating addition, half-adder/subtractor
chains) maps directly to bitstream operations.

## Dataset

All data is **synthetic**. Texts and patterns use the DNA alphabet (A, C, G, T):

- **Unit tests**: Exact match, single substitution, single insertion, two
  substitutions, full mismatch
- **Multi-text batch**: 8 texts compared against one pattern simultaneously
- **Random batches**: 50 batches of 16 random texts (lengths 3-9) with random patterns,
  fully verified against scalar DP reference
- **Wide generated tests**: 1K, 10K, and 1M texts with N=6-8, M=4, spot-checked
  against reference

The DNA alphabet is a natural fit: edit distance on DNA sequences is a fundamental
operation in bioinformatics (sequence alignment, variant calling, read mapping).

## Tutorial

### How Myers' algorithm works

The standard DP for edit distance fills an (M+1) x (N+1) matrix. Myers observed that
the *differences* between adjacent cells in a column are always -1, 0, or +1. These
deltas can be encoded as two bit-vectors:

- **Pv[k]** = 1 if the delta at row k is +1 (positive vertical)
- **Mv[k]** = 1 if the delta at row k is -1 (negative vertical)

At each text position j, the algorithm:
1. Computes an equality vector **Eq** (which pattern positions match the current text character)
2. Updates the delta vectors using carry-propagating addition and boolean logic
3. Adjusts the final distance based on the MSB of the horizontal deltas

### Per-position update (core of the algorithm)

```
Xv = Eq | Mv
T1 = Eq & Pv
T2 = T1 + Pv              // carry-propagating addition
Xh = (T2 ^ Pv) | Eq
Ph = Mv | ~(Xh | Pv)
Mh = Pv & Xh

// Update distance by MSB
if Ph[M-1]: distance += 1  // half-adder chain (increment)
if Mh[M-1]: distance -= 1  // half-subtractor chain (decrement)

// Shift and update
Pv' = Mh_shifted | ~(Xv | Ph_shifted)
Mv' = Ph_shifted & Xv
```

**Operation count per text position:** 24M + 5B ops, where M is the pattern length and
B = max(N, M).bit_length() (equivalently ceil(log2(max(N,M)+1))) is the bit-width of
the distance counter — wide enough to represent the maximum possible distance max(N, M).

### How bitstreams parallelize this

In the bitstream model, each bit position represents a different text. When we compute
`Xv = Eq | Mv`, this ORs the corresponding bit-vectors for ALL K texts simultaneously.

The key patterns used:
- **Ripple-carry addition**: `T2 = T1 + Pv` via a full-adder carry chain (5M ops)
- **Half-adder chain**: distance increment when Ph[M-1] is set (2B ops)
- **Half-subtractor chain**: distance decrement when Mh[M-1] is set (3B ops)

The half-subtractor (decrement) chain is unique to this domain — no other benchmark
uses it.

### Using the program from Python

```python
from simulator.pythonsim import parse
from simulator.pythonsim.interpreter import Interpreter

# Load and parse the program
with open("benchmark/apps/edit_distance/src/edit_distance.bs") as f:
    program = parse(f.read())

# Compare 2 texts against the pattern "ACGT"
# Text 0: "ACGT" (exact match, distance = 0)
# Text 1: "ACGA" (one substitution, distance = 1)
N, M, B = 4, 4, 3

input_arrays = {
    "pos_A": {0: 0b11, 1: 0b00, 2: 0b00, 3: 0b10},  # both 'A' at pos 0; text 1 'A' at pos 3
    "pos_C": {0: 0b00, 1: 0b11, 2: 0b00, 3: 0b00},   # both 'C' at pos 1
    "pos_G": {0: 0b00, 1: 0b00, 2: 0b11, 3: 0b00},   # both 'G' at pos 2
    "pos_T": {0: 0b00, 1: 0b00, 2: 0b00, 3: 0b01},   # text 0 'T' at pos 3
    # ... (pattern equality masks and dist_init omitted for brevity)
}

interp = Interpreter()
result = interp.run(program, inputs={}, params={"N": N, "M": M, "B": B},
                    input_arrays=input_arrays)
```

## .bs Program Details

The complete program is in `edit_distance.bs` (155 lines). It has four sections:

### 1. Declarations

```
param int N                      // text length
param int M                      // pattern length
param int B                      // bit-width of distance counter

input stream pos_A[N], pos_C[N], pos_G[N], pos_T[N]   // text character indicators
input stream eq_A[M], eq_C[M], eq_G[M], eq_T[M]       // pattern equality masks
input stream dist_init[B]        // initial distance M in binary (broadcast)

output stream dist[B]            // final edit distance in bitsliced binary
```

### 2. Initialization

Sets Pv to all-ones (initial vertical deltas are +1 since distance starts at M),
Mv to all-zeros, and copies `dist_init` to `dist`.

### 3. Main loop (N text positions)

For each text position j, computes the 10-step update:
1. **Eq** computation from character indicators (7M ops)
2. **Xv** = Eq | Mv (M ops)
3. **T1** = Eq & Pv (M ops)
4. **T2** = T1 + Pv via ripple-carry addition (5M ops)
5. **Xh** = (T2 ^ Pv) | Eq (2M ops)
6. **Ph** = Mv | ~(Xh | Pv) (3M ops)
7. **Mh** = Pv & Xh (M ops)
8. Distance update: increment/decrement by MSB of Ph/Mh (5B ops)
9. Shift Ph and Mh left by 1 (free array copy)
10. Update Pv, Mv (4M ops)

### Operation count

- **Per text position**: 24M + 5B bitwise operations
- **Total**: N * (24M + 5B) ops
- **Example** (N=8, M=4, B=4): 8 * (96 + 20) = 928 ops

### DSL features used

| Feature | Used? | Notes |
|---------|-------|-------|
| AND (`&`) | Yes | Equality matching, carry logic, subtractor |
| OR (`\|`) | Yes | Character class union, delta vector update |
| XOR (`^`) | Yes | Half-adder/subtractor sums, delta computation |
| NOT (`~`) | Yes | Complement in Ph computation, borrow logic |
| Stream arrays | Yes | `pos_A[N]`, `Pv[M]`, `dist[B]`, etc. |
| For loops | Yes | Main loop over N positions + inner loops over M |
| Nested for | Yes | Double-nested: outer over N, inner over M |
| Parameters | Yes | `param int N`, `param int M`, `param int B` |
| ZERO | Yes | Initialize Mv, carry |
| ONES | Yes | Initialize Pv, Ph_shifted[0] |
| SHIFT | No | |
| ADD (+) | No | (carry-propagating add built from half-adders) |
| Popcount | No | |
