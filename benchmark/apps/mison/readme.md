# Mison JSON Structural Index -- Bitstream Benchmark

## Overview

The Mison benchmark implements a **JSON structural-character bitmap pipeline** using
bitstream programs. Given a stream of JSON text (represented as 8 Parabix basis
bit-planes), it identifies every structural character -- `{`, `}`, `[`, `]`, `:`, and
`,` -- that is **not** inside a string literal. This is a critical first step in
high-performance JSON parsing: once you know where the real structural characters are,
you can jump directly to the fields you need without scanning the entire document.
The kernel produces the level-0 structural-character bitmap consumed by canonical Mison
and simdjson; it does not build Mison's leveled colon/brace indexes and does not
perform pseudo-structural detection or UTF-8 validation. The contract assumes
ASCII-normalized input (`b[7]=0`); the committed datasets meet this contract.

This benchmark uses almost every feature of
the DSL (AND, OR, XOR, NOT, stream addition, SHIFT, arrays, for-loops, params, and the
ONES constant), and it implements a full **4-stage processing pipeline** in 130 lines
of `.bs` code. The program runs in **60 + 2*LOG_W operations** for any stream width.

The benchmark draws from two landmark papers in high-performance JSON parsing:

- **Mison** -- Li et al., "Mison: A Fast JSON Parser for Data Analytics", VLDB 2017.
  Mison introduced the idea of building a structural index over raw JSON text using
  SIMD bit-parallel operations.

- **simdjson** -- Langdale and Lemire, "Parsing Gigabytes of JSON per Second",
  VLDB Journal 2019. simdjson refined and optimized the pipeline, in particular the
  escape-detection stage that uses carry-propagating addition to handle backslash runs
  efficiently.

The original Mison and simdjson implementations classify characters with SIMD byte
comparisons that produce per-character bitmaps. The BitstreamZoo port models the
same pipeline on the **Parabix** transposition: input text is decomposed into 8
bit-planes (one per bit of an ASCII byte), and all character classification is done
with bitwise Boolean operations on those planes.

## Dataset

The benchmark uses a mix of **synthetic** and **real-world** inputs:

- **Fixed test vectors**: 7 hand-crafted JSON strings covering progressively harder
  scenarios: empty object (`{}`), simple key-value, nested objects and arrays, escaped
  quotes, escaped backslashes (even-length runs), mixed escapes (odd-length runs), and
  a string with every structural character type present.
- **Random test vectors**: 100 randomly generated JSON strings targeting 64 bytes
  (actual lengths 50-63) and 50 randomly generated JSON strings targeting 256 bytes
  (actual lengths 241-255).
- **Large-scale**: 1M-bit-wide basis streams generated with `getrandbits()`. The
  output is validated by two checks: a global `structural & str_mask == 0`
  invariant, plus a 200-position spot-check that each sampled character is
  classified correctly relative to `str_mask`.
- **Real-world JSON**: Three optional GH Archive datasets at increasing
  scale, used as real-data checks separate from the canonical synthetic
  tiers:
  - **GH Archive 1M** (1M chars): generated by `make_data.py` into
    `datasets/small/` (not committed)
  - **GH Archive 10M** (10M chars): generated by `make_data.py` into
    `datasets/medium/` (git-ignored)
  - **GH Archive 100M** (100M chars): generated by `make_data.py` into
    `datasets/large/` (git-ignored; raw input fetched by `build.py`)

Validation differs by category. Fixed and random tests compare the bitstream program
output against a Python reference (`mison_reference()`) that computes
`real_quote`, `str_mask`, and `structural` using character-by-character logic.
Tier tests use `mison_bitstream_reference()`, a direct Python emulation of the `.bs`
program over basis streams, plus a structural-vs-string invariant check and a 200
random-position spot-check on character classification. The Large 1M-bit wide test
stores the bitstream interpreter's own output as the expected reference, with the
same invariant and spot-check applied at generation time. Generated GH Archive tests
have no precomputed expected output and are validated at run time via the same
invariant and spot-check.

### Optional GH Archive real-world datasets

These are the optional real-data inputs above. The canonical benchmark
tiers are the synthetic `.bsdata` files at 33.3M/333M/3.33B characters
(see `tier_config.py`); none of the GH Archive `.npz` files are
committed (see below).

**Source**: GH Archive hourly event dump (real GitHub API JSON data from
`https://data.gharchive.org/`). The raw UTF-8 text is normalized to ASCII (non-ASCII
bytes are replaced) and masked to 7 bits, then decomposed into 8 Parabix basis
bit-planes for use with the Mison structural index pipeline. The high bit-plane `b7`
is therefore all zero on the generated datasets.

**Streams**: 8 basis bit-planes (b0..b7), following the Parabix byte decomposition
where b[k] contains bit k of the ASCII code at each character position.

| Tier | File | Size | Description |
|------|------|------|-------------|
| small | `gharchive_1m.npz` | ~1 MB | 1M characters of GitHub event JSON |
| medium | `gharchive_10m.npz` | ~10 MB | 10M characters of GitHub event JSON |
| large | `gharchive_100m.npz` | ~100 MB | 100M characters of GitHub event JSON |

None of these are committed: `python build.py mison` downloads the GH
Archive dump and `make_data.py` derives them locally. The dump contains
real GitHub event data (usernames, commit emails), so extracts are not
redistributed with the suite; the tests that use them are optional and
skipped when the files are absent.

### Real-world scale context

JSON text processing naturally scales to very large streams. A 1M-bit stream represents
1 million character positions processed simultaneously. On a GPU with 64-bit words,
this corresponds to roughly 15,625 words of SIMD parallelism -- suitable for
high-throughput JSON parsing of multi-megabyte documents.

## Tutorial

### The problem

Consider this JSON string:

```
{"name":"say \"hi\""}
```

The escaped quotes appear at positions 14 and 18 (each preceded by a backslash at 13
and 17). They are *escaped* -- they sit inside the string and are not real delimiters.
The structural characters `{`, `:`, and `}` at positions 0, 7, and the final position
(20) are outside strings. The pipeline must distinguish all of these correctly.

### Stage 1: Character Classification

The input arrives as 8 Parabix basis bit-planes, `b[0]` through `b[7]`, where `b[k]`
contains bit `k` of the ASCII code at each character position. For example, the
double-quote character `"` has ASCII code 0x22 (binary 00100010), so it has bits 1 and
5 set.

This stage extracts a separate bitstream for each character class of interest:

| Character | ASCII (hex) | Binary     |
|-----------|-------------|------------|
| `"`       | 0x22        | 00100010   |
| `\`       | 0x5C        | 01011100   |
| `{`       | 0x7B        | 01111011   |
| `}`       | 0x7D        | 01111101   |
| `[`       | 0x5B        | 01011011   |
| `]`       | 0x5D        | 01011101   |
| `:`       | 0x3A        | 00111010   |
| `,`       | 0x2C        | 00101100   |

Each character is identified by ANDing together the appropriate basis bits (or their
complements). For example, to detect `"` (0x22), the program checks:
`~b[6] & b[5] & ~b[4] & ~b[3] & ~b[2] & b[1] & ~b[0]`.

The implementation shares common sub-expressions (like `b[3] & b[4]`) across multiple
character checks. The braces and brackets share a common prefix pattern and are split
by differing bits. This stage costs approximately **37 operations**.

### Stage 2: Escape Detection

Not every `"` in the input is a real quote. A quote preceded by an odd number of
backslashes is escaped and should be ignored. The challenge is that backslashes
themselves can be escaped: `\\` is an escaped backslash, so `\\"` contains a *real*
quote (preceded by an even-length backslash run).

The simdjson algorithm handles this elegantly:

1. Find the **start** of each backslash run (a `\` not preceded by another `\`).
2. Separate starts into those at **even** positions and **odd** positions.
3. Use **stream addition** to propagate carries through each backslash run. Adding the
   start position to the backslash mask causes a carry to ripple through the consecutive
   backslashes, landing on the first non-backslash character after the run.
4. Check where the carry lands: if a carry from an even-position start lands on an odd
   position (or vice versa), the run has odd length, meaning the next character is
   escaped.

```
bs_starts    = backslash & ~(backslash << 1)
even_starts  = bs_starts & even_bits
odd_starts   = bs_starts & odd_bits
even_carries = (even_starts + backslash) & ~backslash
odd_carries  = (odd_starts + backslash) & ~backslash
odd_ends     = (even_carries & odd_bits) | (odd_carries & even_bits)
real_quote   = quote & ~odd_ends
```

The key insight is that stream addition (`+`) with carry propagation naturally handles
runs of any length. This stage costs approximately **16 operations**, including 2
additions.

### Stage 3: String Mask via Prefix XOR

Once we know where the real (unescaped) quotes are, we need to mark every position that
falls inside a string literal. A position belongs to a string if an odd number of real
quotes appear at-or-before it.

This is computed using **inductive doubling** (also called prefix XOR):

```
str_mask = real_quote
for i in 0..LOG_W:
    str_mask = str_mask ^ (str_mask << stride)
    stride = stride * 2
```

Starting with stride 1, each iteration doubles the reach. After `LOG_W` iterations
(where `LOG_W = ceil(log2(stream_width))`), every bit carries the XOR parity of all
real-quote bits at-or-before it. Under this convention, the opening quote of each
string is included in `str_mask` while the closing quote is excluded. Structural
filtering is unaffected because quotes are not structural characters.

This stage costs **2 * LOG_W operations** (one XOR and one SHIFT per iteration). For
64-bit streams, that is 12 ops; for 1M-bit streams, 40 ops.

### Stage 4: Structural Filtering

Finally, OR together all six structural character streams and mask out any positions
that fall inside strings:

```
structural = (lbrace | rbrace | lbracket | rbracket | colon | comma) & ~str_mask
```

This stage costs approximately **7 operations**.

### Total Operation Count

| Stage | Operations | Notes |
|-------|-----------|-------|
| 1. Character classification | ~37 | Fixed, no loops |
| 2. Escape detection | ~16 | Includes 2 stream additions |
| 3. String mask | 2 * LOG_W | 12 for 64-bit, 40 for 1M-bit |
| 4. Structural filtering | ~7 | Fixed, no loops |
| **Total** | **60 + 2 * LOG_W** | **72 for 64-bit, 100 for 1M-bit** |

## .bs Program Details

Code below is shown in compound form for readability; the shipped
`src/mison.bs` is its 3-address expansion.

The full program lives at `src/mison.bs` (130 lines). Here is how it is organized.

### Declarations

```
input stream b[8]           // 8 Parabix basis bit-planes (b[0]=LSB .. b[7]=MSB)
input stream even_bits      // alternating 0x5555... pattern
param int LOG_W             // log2(stream width), controls prefix XOR depth

output stream structural    // JSON structural chars outside strings
output stream str_mask      // bit positions inside string literals
output stream real_quote    // unescaped quote positions
```

The program takes 9 input streams (8 basis planes plus the even-bits constant), one
integer parameter, and produces 3 output streams.

### Stage 1: Character Classification (lines 29-83)

Computes negated basis bits for reuse, then builds each character class stream from
AND/NOT combinations:

```
stream nb0 = ~b[0]
stream nb1 = ~b[1]
// ... (negations of b[0] through b[6])

// Shared sub-expressions
stream b3_b4 = b[3] & b[4]
stream low   = nb6 & b[5]
stream high  = b[6] & b3_b4

// Quote " (0x22 = 00100010)
stream quote = low & nb4 & nb3 & nb2 & b[1] & nb0

// Backslash \ (0x5C = 01011100)
stream backslash = high & nb5 & b[2] & nb1 & nb0

// Brackets share a common base: b[0]=1, b[3]=1, b[4]=1, b[6]=1
stream bracket_base = high & b[0]
stream open  = bracket_base & b[1] & nb2    // { and [
stream close = bracket_base & nb1 & b[2]    // } and ]
stream lbrace   = open & b[5]               // { has b[5]=1
stream rbrace   = close & b[5]              // } has b[5]=1
stream lbracket = open & nb5                // [ has b[5]=0
stream rbracket = close & nb5               // ] has b[5]=0

// Colon : (0x3A) and Comma , (0x2C)
stream colon = low & b3_b4 & nb2 & b[1] & nb0
stream comma = low & nb4 & b[3] & b[2] & nb1 & nb0
```

### Stage 2: Escape Detection (lines 89-106)

Uses stream addition to detect characters escaped by odd-length backslash runs:

```
stream odd_bits  = even_bits ^ ONES
stream bs_shifted = backslash << 1
stream bs_starts = backslash & ~bs_shifted
stream even_starts = bs_starts & even_bits
stream odd_starts  = bs_starts & odd_bits
stream nbs = ~backslash
stream ec_raw = even_starts + backslash      // carry through even-start runs
stream even_carries = ec_raw & nbs
stream oc_raw = odd_starts + backslash       // carry through odd-start runs
stream odd_carries = oc_raw & nbs
stream odd_ends = (even_carries & odd_bits) | (odd_carries & even_bits)
real_quote = quote & ~odd_ends
```

### Stage 3: String Mask (lines 112-119)

Prefix XOR via inductive doubling, parameterized by `LOG_W`:

```
str_mask = real_quote
int stride = 1
for i in 0..LOG_W {
    str_mask = str_mask ^ (str_mask << stride)
    stride = stride * 2
}
```

### Stage 4: Structural Filtering (lines 124-130)

OR together all structural types, then mask out positions inside strings:

```
stream not_str = ~str_mask
stream struct_raw = lbrace | rbrace
struct_raw = struct_raw | lbracket
struct_raw = struct_raw | rbracket
struct_raw = struct_raw | colon
struct_raw = struct_raw | comma
structural = struct_raw & not_str
```

### DSL Features Used

This single program exercises almost the entire DSL feature set:

| Feature | Where used |
|---------|-----------|
| AND (`&`) | Character classification, escape detection, structural filtering |
| OR (`\|`) | Structural filtering, escape detection |
| XOR (`^`) | Prefix XOR string mask, odd-bits computation |
| NOT (`~`) | Basis bit negation, masking |
| Addition (`+`) | Carry propagation through backslash runs (Stage 2) |
| SHIFT (`<<`) | Backslash-start detection, prefix XOR doubling |
| Arrays (`b[8]`) | Input basis bit-planes |
| For-loop | Prefix XOR inductive doubling |
| Params (`LOG_W`) | Controls loop iteration count |
| ONES | Computing `odd_bits = even_bits ^ ONES` |

This program exercises 10 of 13 DSL features.

## Running

### Prerequisites

Make sure you are in the project root directory and have Python 3 available.
The core 13 tests run on the standard library alone. The three optional GH
Archive tests load `.npz` data via NumPy; if NumPy is not installed, those
tests are silently skipped and 13 (not 16) tests will run.

python3 benchmark/apps/mison/src/run.py
