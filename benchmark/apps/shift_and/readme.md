# DNA Shift-And — Bitstream Benchmark

## Overview

This benchmark implements the Shift-And exact string matching algorithm using the
bitstream DSL. It matches a DNA pattern of length M against a text, where each bit
position represents one character position in the text. All positions are processed in
parallel.

The Shift-And algorithm was introduced by:

> Baeza-Yates & Gonnet, "A New Approach to Text Searching",
> *Communications of the ACM* 35(10), 1992.

The idea is to encode partial match states as bits in a machine word and advance all of
them simultaneously with shifts and masks. For patterns shorter than the word size, the
algorithm runs in O(N) time for a text of length N.

The bitstream formulation used in this benchmark follows the Parabix framework:

> Lin et al., "Parabix: Boosting the Efficiency of Text Processing on Commodity Processors",
> *Proceedings of the IEEE International Symposium on High-Performance Computer Architecture (HPCA)*, 2012.

Following the Parabix bitstream model, the text is encoded as per-character
*character-class bitstreams* (one indicator stream per nucleotide), and the
Shift-And state update becomes a sequence of bitwise operations on those streams. This
is the representation our DSL uses. (In strict Parabix terminology, "basis bitstreams"
are the bit-planes of byte-encoded text; the per-character indicator streams used here
are character-class bitstreams derived from those basis bit-planes.)

This benchmark is one of the clearest examples of the Parabix approach: a classic
bit-parallel algorithm, originally designed for scalar words, is lifted into a bitstream
program where each bit position represents a different character in the text.

## Tutorial

### The original Shift-And algorithm

Given a pattern `P[0..M-1]` and a text `T[0..N-1]` over an alphabet (here
`{A, C, G, T}`), the scalar Shift-And algorithm works as follows.

**Preprocessing.** For each character `c` in the alphabet, build a bitmask `B[c]` of
length M where bit j is set if `P[j] == c`. Bits below are written left-to-right by
position index (bit 0 leftmost), so each column corresponds to one pattern position:

```
Position:  0 1 2 3
B['A']  =  1 0 0 1   (P = "ACGA" has 'A' at positions 0 and 3)
B['C']  =  0 1 0 0   ('C' at position 1)
B['G']  =  0 0 1 0   ('G' at position 2)
```

Equivalently, in the standard `1 << j` integer representation (bit 0 on the right),
`B['A'] = 0b1001`, `B['C'] = 0b0010`, `B['G'] = 0b0100`.

**Matching.** Maintain a state word `D`, initially 0. For each text character `T[i]`:

```
D = ((D << 1) | 1) & B[T[i]]
```

If bit `M-1` of `D` is set after this update, there is a complete match ending at
position `i`.

**How it works.** Each bit j in `D` tracks whether the first j+1 characters of the
pattern match the text ending at the current position. The left shift moves every
partial match forward by one position. The OR with 1 seeds a fresh match attempt at
position 0 of the pattern. The AND with `B[T[i]]` kills any partial match whose next
expected character does not equal `T[i]`.

The algorithm runs in O(N * ceil(M/w)) time, where w is the machine word size.

Here is the Python reference implementation:

```python
def shift_and_reference(text, pattern):
    m = len(pattern)
    B = {}
    for c in "ACGT":
        mask = 0
        for j in range(m):
            if pattern[j] == c:
                mask |= 1 << j
        B[c] = mask

    R = 0
    match_bit = 1 << (m - 1)
    matches = set()
    for i, c in enumerate(text):
        R = ((R << 1) | 1) & B.get(c, 0)
        if R & match_bit:
            matches.add(i)
    return matches
```

### Adaptation to bitstream programs

In the scalar algorithm, each bit in the state word `D` corresponds to one *pattern
position*. The algorithm iterates over text characters one at a time.

In the bitstream formulation, the roles of bits and iterations are swapped:

- Each **bit position** in a stream corresponds to one **text character**.
- The program **iterates over pattern positions** (the `for` loop).

This transposition is the core Parabix insight. Instead of processing one character at
a time with M bits of state, we process all N text positions at once for each of the M
pattern positions.

| Aspect | Scalar Shift-And | Bitstream Shift-And |
|--------|-----------------|---------------------|
| Each bit represents | A pattern position | A text position |
| Outer loop iterates over | Text characters (N) | Pattern positions (M) |
| State word width | M bits | N bits |
| Parallelism | M partial matches at once | N text positions at once |

### Encoding the text as character-class bitstreams

The DNA text is represented by four per-character indicator streams, each N bits wide:

| Stream | Bit k is 1 if... |
|--------|-------------------|
| `is_A` | `text[k] == 'A'` |
| `is_C` | `text[k] == 'C'` |
| `is_G` | `text[k] == 'G'` |
| `is_T` | `text[k] == 'T'` |

For example, if the text is `ACGTACGT`:

```
Position:  0 1 2 3 4 5 6 7
Text:      A C G T A C G T

is_A:      1 0 0 0 1 0 0 0
is_C:      0 1 0 0 0 1 0 0
is_G:      0 0 1 0 0 0 1 0
is_T:      0 0 0 1 0 0 0 1
```

### Encoding the pattern as mask arrays

The pattern is encoded as four arrays of streams, `mask_A[j]`, `mask_C[j]`,
`mask_G[j]`, `mask_T[j]`, for j = 0, ..., M-1. Each entry is either `ONES` (all bits
set) or `ZERO`:

```
mask_X[j] = ONES   if P[j] == X
mask_X[j] = ZERO   otherwise
```

These masks select which character-class (indicator) stream to use at each pattern
position.

### Computing character matches

For pattern position j, the *character match stream* `cm[j]` has bit k set wherever
`text[k]` matches `P[j]`:

```
cm[j] = (is_A & mask_A[j]) | (is_C & mask_C[j])
      | (is_G & mask_G[j]) | (is_T & mask_T[j])
```

Since exactly one of the four masks is `ONES` and the rest are `ZERO`, this reduces to
selecting the indicator stream for whichever character appears at position j in the
pattern.

The four-way OR with masks is used (rather than a conditional) because the DSL has no
data-dependent control flow -- all indices must be computable from parameters and loop
variables.

### Trace example

Text: "ACGATCG", Pattern: "CG" (M=2)

```
is_A: 1..1...   is_C: .1...1.   is_G: ..1...1   is_T: ....1..

Position 0 (pattern[0] = 'C'):
  R = is_C = .1...1.     // R[k]=1 where text[k]='C'

Position 1 (pattern[1] = 'G'):
  cm = is_G = ..1...1
  R = (R << 1) & cm
  R << 1 = ..1...1.      // shift partial matches forward
  R = ..1...1. & ..1...1  = ..1...1
```

Result: matches at positions 2 and 6 -- "A**CG**AT**CG**". Correct!

## .bs Program Details

The program logic, shown here in compound form for readability (the
shipped `shift_and.bs` is its 3-address expansion):

```
param int M

input stream is_A
input stream is_C
input stream is_G
input stream is_T

input stream mask_A[M]
input stream mask_C[M]
input stream mask_G[M]
input stream mask_T[M]

output stream matches

// Character match for position 0
stream R = (is_A & mask_A[0]) | (is_C & mask_C[0])
         | (is_G & mask_G[0]) | (is_T & mask_T[0])

// Process remaining pattern positions
for j in 1..M {
    stream cm = (is_A & mask_A[j]) | (is_C & mask_C[j])
              | (is_G & mask_G[j]) | (is_T & mask_T[j])
    R = (R << 1) & cm
}

matches = R
```

- **16 op templates** in the source (7 init + 9 in the loop body); after unrolling the
  for-loop the program has `9M - 2` ops with a flat critical path of `2M + 1`
  (e.g., M=8 -> 70 ops, depth 17; M=32 -> 286 ops, depth 65).
- After the loop, `matches[k] = 1` means `text[k-M+1..k]` matches the entire pattern.

### Line-by-line walkthrough

**`param int M`** -- The pattern length, provided at runtime. It controls the loop
bound and the size of the mask arrays.

**`input stream is_A, is_C, is_G, is_T`** -- The four character-class (indicator)
streams encoding the DNA text. Each is N bits wide, where N is the text length.

**`input stream mask_A[M], mask_C[M], mask_G[M], mask_T[M]`** -- Four arrays of M
streams each, encoding the pattern. Entry j is either `ONES` or `ZERO`.

**`output stream matches`** -- The result. Bit k is set if the pattern matches ending
at text position k.

**First character match (j = 0)**: Computes where text characters match `P[0]` and
stores the result in R. Cost: 4 AND + 3 OR = 7 ops.

**Loop body (j = 1, ..., M-1)**: Computes the character match for position j (4 AND +
3 OR = 7 ops), shifts R left by 1 (1 SHIFT), and combines with AND (1 AND). Cost per
iteration: 7 + 1 + 1 = 9 ops.

**`matches = R`** -- A copy (not counted as an op).

### Op count

Total: 7 + 9 * (M - 1) = **9M - 2** operations.

| Pattern length | Ops   |
|----------------|-------|
| 1              | 7     |
| 4              | 34    |
| 8              | 70    |
| 16             | 142   |
| 32             | 286   |

The op count depends only on the pattern length M; the text length N
determines the *width* of the streams.
This is what makes the bitstream approach attractive for GPU execution: a single
program of 286 operations can match a 32-character pattern against 10 million text
positions simultaneously.

### DSL features used

| Feature | Used? | Notes |
|---------|-------|-------|
| AND (`&`) | Yes | Character matching and state filtering |
| OR (`\|`) | Yes | Combining character-class stream selections |
| SHIFT (`<< 1`) | Yes | Advancing partial matches by one text position |
| Arrays | Yes | `mask_A[j]` -- parameterized pattern encoding |
| For-loop | Yes | `for j in 1..M` -- iterating over pattern positions |
| Param | Yes | `param int M` -- runtime-specified pattern length |
| XOR | No | |
| NOT | No | |
| ADD (+) | No | |
| Popcount | No | |

pass (12 committed file-backed + 1 generated at run time + 3 locally generated tier
file-backed). The 5 optional entries additionally run when their data is present: the
committed chr1 2M `.npz` runs by default, while chr1 20M/200M, SARS-CoV-2, and E. coli
require their `.npz`/FASTA generated or downloaded first.

Most tests compare the bitstream result against the scalar Python reference
implementation on the full reconstructed text. The 10M-bp wide test
generates the four character-class indicator streams directly via
`getrandbits(N)` (avoiding the O(N) cost of character-by-character
transposition), reconstructs the full text from those streams, then runs
the full scalar check. For
file-backed genomes above 10M bp (chr1 20M and 200M), random windows
are spot-checked against the scalar reference to avoid Python-level
loops over hundreds of millions of characters. Tier `.bsdata` files
store precomputed expected match streams generated by a direct
bitstream Shift-And reference; correctness is established at
generation time, and runtime verification compares the bitstream
result against the stored expected output, with file integrity tracked
via SHA-256 provenance.
