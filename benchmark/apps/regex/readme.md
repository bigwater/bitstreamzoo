# Regex: icgrep-derived regex stress kernel from Snort-pattern inputs

icgrep-compiled bitstream programs over AutomataZoo Snort-pattern inputs, using
the Parabix byte-decomposition methodology (Cameron et al., 2014). The
kernel follows icgrep's anchor-free, all-position semantics.

## Overview

Each input byte is decomposed into 8 basis bit-planes `b[0..7]`.
Character classes are compiled to Boolean formulas over these bit-planes
(e.g., `\d` becomes a formula over b0..b7 that is true for bytes 0x30-0x39).
Pattern matching uses marker propagation: a marker bitstream tracks which
positions are valid match continuations, advanced left by one position per
character consumed.

The MatchStar operation `(((m & c) + c) ^ c) | m` extends markers through
runs of characters matching a class (Kleene star/plus).

## Patterns

Patterns come from the Snort IDS ruleset shipped with the AutomataZoo
benchmark suite (Wadden et al., IISWC 2018; `Snort/benchmarks/automata/snort.regex`).
From 2,396 unique PCRE patterns, 2,312 are produced by icgrep's Pablo IR
pipeline; the remaining 84 fail icgrep compilation. 42 of the 2,312 surface
as trivial-output stubs (the Pablo kernel reduces to ZERO under unsupported
constructs — 25 counted repetitions `{n}`/`{n,m}`, 2 non-greedy `*?`/`+?`,
and 15 with literal newline
requirements, zeroed under icgrep's line-based model), so 2,270
patterns are semantically active in
the generated `.bs` programs.  Because patterns are sorted by op count
ascending, the 42 stubs cluster at the bottom of the manifest and disproportionately
populate the small tier (84 % of `regex_small`).

The generated `.bs` programs use an **anchor-free, all-position** variant of
the Snort patterns: leading `^` is stripped before compilation, and `$`/EOF
maps to `ONES` in the converter (`pablo_to_bs.py`).  PCRE `/s` (DOTALL) and
`/m` (multiline) flags are **not** honoured: icgrep's CLI has no switch for
them; the programs follow icgrep's semantics.
So `.` always means "not newline" and `^`/`$` are absorbed by the anchor-free
model regardless of `/m`.

Two further pre-processor simplifications (`pablo_to_bs.py` rewrites the
pattern before icgrep sees it) also diverge from PCRE:

- `\s`/`\S` expand to the fixed ASCII set `[\x09\x0a\x0d\x20]` (HT, LF,
  CR, SPACE).  PCRE's default `\s` additionally includes VT (`\x0b`) and
  FF (`\x0c`), so a generated `\s` does **not** match those two bytes
  (e.g. `snort_1293` `/^C2\s\d+/i` misses `C2\x0b5` and `C2\x0c5`).
- Case-insensitive `/i` is applied only to letters **outside** character
  classes; letters inside `[...]` stay case-sensitive (e.g. `snort_1654`
  `/^\x2F[GL]R/i` matches `\x2FGR` but not `\x2Fgr`).  25 / 126 (medium / large) of the
  active medium/large patterns carry `/i` with a letter-bearing class.

Each program reflects icgrep run on the pre-processed pattern. These
deviations are **not** among the Python `re` cross-check filters below.

Three tiers of increasing complexity (nested: small ⊂ medium ⊂ large),
sorted by op count ascending:

| Program | Patterns | Active | Stubs | Ops | Input Streams | Description |
|---------|----------|--------|-------|-----|---------------|-------------|
| regex_small | 50 | 8 (16 %) | 42 | 271 | 8 | Lowest-complexity patterns; stub-dominated |
| regex_medium | 500 | 458 (92 %) | 42 | 52,034 | 8 | Moderate complexity |
| regex_large | 2,312 | 2,270 (98 %) | 42 | 1,211,513 | 8 | All compilable patterns |

All programs have 8 input streams (basis bit-planes b[0..7]) and a single
`output stream any_match` (OR of all per-pattern match results). Individual
per-pattern match streams are computed internally but not exported.

Pattern selection is driven by `pattern_manifest.json` (generated by
`curate_patterns.py`), which compiles all 2,396 patterns, records
success/failure and op count, and sorts by op count ascending.

### Memory Requirements

The CPU raw interpreter keeps ALL variables alive by default. For regex_large
on the small tier (`bitlength = 44,444,444` bits → 5.56 MB per stream):
- ~1.27M variables × 5.56 MB ≈ **7.1 TB** without optimization (infeasible)

With `--reuse-mem` (liveness-based register reuse):
- measured `max_live` = 2,357 registers
- 2,357 × 5.56 MB ≈ **13 GB**

**Important**: Always use `--reuse-mem` with regex_large for tier data.

## Compilation Pipeline

```
Snort PCRE pattern
    -> curate_patterns.py (compile all 2,396, sort by ops)
    -> pattern_manifest.json (2,312 successful)
    -> compile_all.py (select 50/500/all from manifest)
    -> icgrep --ShowPablo (Parabix regex compiler)
    -> Pablo IR (intermediate representation)
    -> pablo_to_bs.py (Pablo IR to 3-address .bs converter)
    -> 3-address .bs code
```

The icgrep compiler (Cameron et al., 2014) handles regex-to-bitstream compilation:
character class decomposition into Boolean formulas over basis bits b[0..7],
marker propagation for sequence/alternation/repetition, and MatchStar expansion
for Kleene star/plus into carry-propagating addition formulas.

The `pablo_to_bs.py` converter maps Pablo IR primitives to .bs DSL operations:
Advance to shift, MatchStar to 4-op carry formula, Sel to 4-op MUX,
ScanThru to 3-op add-and-mask, and packed byte comparisons to Boolean
circuits over basis bits.

## Verification

The `any_match` output is the OR of all per-pattern match streams. The
generated `.bs` programs are a mechanical translation of icgrep's Pablo
IR (`compile_all.py` → `icgrep --ShowPablo` → `pablo_to_bs.py`), so
**icgrep is the reference by construction** — the bitstream model
follows whatever icgrep produces, not PCRE.

Python `re` is used as a convenience cross-check.  It approximates the
all-position match set but **does not match icgrep's semantics on every
pattern**.  Known divergences excluded from the Python `re` reference:

| Filter | Cause | Count (medium / large) |
|--------|-------|-----------------------:|
| Stubs (`op_count ≤ 5`) | Pablo kernel reduces to ZERO (counted repetitions, mixed features) | 42 / 42 |
| Non-greedy `*?`, `+?`, `??` | icgrep returns all-position match set, PCRE returns leftmost-shortest | 36 / 403 |
| `/s` + bare `.` | icgrep CLI has no DOTALL switch; PCRE with `/s` lets `.` match newline | 18 / 69 |

After filtering, the spot-check picks one 64 KB contiguous slice at a
random offset and asserts `REF ⊆ BS` across every remaining pattern.

icgrep itself is also available as an existence cross-check
(`icgrep_existence_check()` in `generate_tests.py`): if icgrep reports
any match for a pattern in a hand-crafted payload, the `any_match`
output must be non-zero somewhere.

## Key DSL Features Exercised

- `+` (stream addition) via MatchStar for Kleene star/plus
- Character classification via Boolean formulas over basis bit-planes
- `<<` (shift) for marker advance
- `ONES` for initial marker (match can start at any position)
- Shared sub-expression elimination across patterns
